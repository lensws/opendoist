# OpenDoist

Самостоятельный веб-менеджер задач с распознаванием дат на русском и английском. Вход по паролю, SQLite, повторения, история и экспорт. Распознавание дат работает без LLM и внешних API. Email и Telegram подключаются по желанию. GPL-3.0.

**Развёртывание:** [установка на чистый VPS, HTTPS и резервные копии](deploy/README.md). Для двух окружений: [prod и beta на одном сервере](deploy/VPS.md). Приложение личное: один общий список и один пароль; многопользовательского разделения пока нет.

**CI/CD:** работаем в `beta`, которая автоматически обновляет тестовый сайт после тестов. После проверки сайта напишите агенту «выкатывай на основной»: он перенесёт проверенный коммит в `main`, а CI повторно проверит и развернёт его. PR и ручные кнопки GitHub не нужны. [Как работает деплой](deploy/automation/README.md).

## Быстрая установка на Linux

```bash
curl -fsSL https://raw.githubusercontent.com/lensws/opendoist/beta/install/install.sh | sudo bash
```

Мастер спросит домен и пароль, подготовит Docker на Ubuntu/Debian, запустит приложение и при указанном домене настроит HTTPS. Скрипт публикуется из beta; приложение по умолчанию устанавливается из main. Для тестовой версии используйте `sudo bash -s -- --ref beta` вместо `sudo bash`. Повторный запуск сохраняет настройки и данные.

[Требования, параметры, SSH-туннель, обновление и резервные копии](install/README.md). Для уже настроенных prod/beta используется прежний процесс деплоя.

## Запуск

Для локального запуска нужен Node.js 24+:

```sh
npm ci
cp .env.example .env
# Задайте собственный OPENDOIST_PASSWORD в .env (минимум 12 символов)
npm start
```

Откройте http://localhost:3000 и войдите с заданным паролем. SQLite создаётся в `data/`, данные сохраняются после перезапуска. `npm test` запускает тесты движка и HTTP API; `npm run demo` показывает примеры парсинга.

## Возможности приложения

- Добавление задач с предпросмотром распознанного срока и следующих повторений.
- Все задачи, сегодня (включая просроченные), предстоящие, выполненные и история.
- Поиск, редактирование названия отдельно от расписания, удаление срока и задачи.
- Завершение повторения переносит срок; последнее выполнение можно отменить.
- Настройки языка и часового пояса, JSON-экспорт, адаптивный интерфейс.
- Светлая, тёмная и системная темы, палитра акцентов и свой цвет. Предпросмотр сразу, сохранение в базе на сервере для всех устройств (включая язык и часовой пояс); отмена возвращает прежнее оформление.
- Напоминания на дату и время или заранее до срока, несколько напоминаний на задачу. Email через SMTP и Telegram Bot API. Ежедневная сводка утром или вечером накануне. [Подключение уведомлений](deploy/NOTIFICATIONS.md).
- Импорт и экспорт JSON в настройках: перенос задач, сроков, повторений, напоминаний, истории и заметок. Импорт добавляет только новые ID, не перезаписывая существующие задачи; перед записью показывает количество новых задач и дублей. До 10 000 задач. Для текста заметок нет ограничения длины в приложении. Настройки каналов и секреты не переносятся; прошедшие напоминания не рассылаются заново. Экспорт содержит последние 100 записей истории (для полной резервной копии используйте SQLite backup).
- Проекты и разделы внутри проектов, цветные значки или эмодзи в меню. Задачи без проекта находятся во Входящих. Перенос — в редакторе задачи; удаление проекта сохраняет задачи. Структура включена в JSON-экспорт и импорт.
- Создание задач из личных сообщений Telegram-боту: распознавание RU/EN, выбор проекта через `#Название` или `#"Мой проект"`, команды `/add`, `/help`, `/projects`. Включается отдельно в настройках Telegram; принимаются сообщения только от указанного владельца.
- SQLite, сессии HttpOnly, защита от запросов с посторонних сайтов и лимит попыток входа.

## Совместимость

Ориентир этой версии — [страница Todoist о датах и времени](https://www.todoist.com/ru/help/todoist/features/schedule-a-date-and-time-for-your-todoist-tasks-q7VobO) и её [английская версия](https://www.todoist.com/help/todoist/features/schedule-a-date-and-time-for-your-todoist-tasks-q7VobO), проверенные 2 ноября 2026 года.

Корпус `test/todoist-formats.test.js` покрывает все строки таблицы разовых сроков и перечисленные варианты написания на двух языках. Проверяются итоговая дата, время, извлечение из названия задачи и позиции выделения. Отдельные проверки покрывают составной пример повторения с началом и окончанием, дедлайн, ежегодный день рождения и текстовые сокращения повторений.

Это совместимость с примерами и описанной семантикой статьи, а не проверенная идентичность закрытому парсеру Todoist для любых фраз. В статье есть неточности и неописанные алгоритмы; принятые решения перечислены ниже. Полное покрытие отдельной статьи о повторениях, на которую ведёт ссылка со страницы, в эту версию не входит.

## API

```js
import { parseTask, occurrences, nextAfterCompletion } from './src/index.js';

const task = parseTask('Отчёт каждый 3 вторник начиная с 20 августа заканчивая через 6 месяцев', {
  now: '2026-07-01T10:00:00+03:00',
  timezone: 'Europe/Moscow',
  language: 'ru',
});
console.log(task.title); // Отчёт
console.log(task.due.date); // 2026-09-15
console.log(occurrences(task, { after: '2026-07-01T00:00:00+03:00', count: 10 }));
console.log(nextAfterCompletion(task, '2026-09-15T18:00:00+03:00'));
```

Результат JSON-совместим и содержит:

- `status`: `scheduled`, `unscheduled`, `needs_review`.
- `source`, `title`: исходный текст и название без распознанных фрагментов.
- `due`: локальная дата, время или `null`, IANA timezone, UTC instant или `null`, `allDay`.
- `recurrence`: режим `calendar`/`after_completion`, частота, интервал, локальный `dtstart`, RRULE, timezone.
- `deadline`: независимая дата из фигурных скобок; не перемещается вместе с повторением.
- `dateAction: 'clear'`: явно удалить существующую дату при команде «без срока». Отсутствие найденной даты само по себе не означает удаления.
- `spans`: фрагменты для подсветки; индексы UTF-16, конец не включён, `source.slice(start, end) === text`.
- `warnings`: сообщения о неоднозначности/причинах уточнения (пока на английском).

При `needs_review` исходный текст сохраняется и расписание не создаётся. При `unscheduled` дата не найдена или явно удалена; смотрите `dateAction`. Неверные параметры API вызывают исключение. Потребитель должен проверять `status`, а не только наличие поля.

`occurrences` выдаёт до 100 будущих дат строго после `after`. `nextAfterCompletion` возвращает новый срок, но не изменяет задачу. Приложение должно само сохранить возвращённый срок в `due`. В календарном режиме пропущенные даты пропускаются, досрочное выполнение продвигает расписание за завершаемую дату. В режиме от выполнения новая дата отсчитывается от фактического выполнения.

## Настройки и выбранная семантика

- `language`: `auto` (по умолчанию), `ru`, `en`. Автоопределение выбирает русский при наличии кириллицы; для чисто числовых дат передавайте язык явно. Смешанные тексты не гарантируются.
- `dateOrder`: `DMY` или `MDY`. По умолчанию зависит от языка. Если одно число больше 12, порядок очевиден и определяется автоматически. Форматы с годом в начале поддерживаются отдельно.
- `nextWeekDay`, `weekendDay`: ISO-дни недели 1..7; по умолчанию 1 и 6. Выбирается ближайший такой день строго после текущего дня; следующие выходные — ещё через неделю.
- «Следующий» с конкретным днём недели означает этот день следующей календарной недели. Это следует пояснению в статье, которое точнее короткой строки таблицы.
- В строке `next weekday` слово weekday используется как обозначение конкретного дня. Если написать эту фразу буквально, движок выберет следующий день понедельник–пятница и вернёт предупреждение о выбранной интерпретации.
- Точный алгоритм «на этой неделе» в статье не раскрыт. Наш выбор: ближайшая пятница в текущей неделе; начиная с пятницы — воскресенье, в воскресенье — через неделю. Целевой день можно изменить через `laterThisWeekDay`, по умолчанию 5. Результат содержит предупреждение.
- В русской таблице потеряны обозначения pm. Голое число 1..7 в поле срока считается вечерним часом, 8..12 — утренним. `6` означает 18:00, `27` — день текущего месяца. Внутри названия голые числа не извлекаются, чтобы «Купить 6 яиц» оставалось задачей без срока. Используйте `в 6`, `27th` или полную дату.
- Время с двоеточием — 24-часовое; am/pm и «утра/вечера» задают период явно. Во фразе даты принимается и компактное время из четырёх цифр. Отдельного UI-поля времени, в котором Todoist запрещает такой формат, здесь нет.
- Время без даты выбирает ближайший будущий момент; явная дата может иметь уже прошедшее время. Дата без времени остаётся целым днём, без фиктивного UTC instant.
- В русской формуле про 50 дней до Нового года статья приводит результат для 31 декабря, а не 1 января. Для этой относительной формулы используем 31 декабря, как в английском оригинале. Самостоятельное «новый год» означает 1 января.
- Относительное окончание повторения считается от `now`, абсолютная конечная дата включается целиком. RRULE хранится вместе с локальным стартом и timezone; один RRULE не является полным экспортом расписания.
- Месячные/годовые сдвиги разовых дат и повторения от выполнения округляют отсутствующий день к концу месяца. Календарные повторения 31-го и 29 февраля пропускают месяцы/годы без нужной даты.
- Календарные интервалы привязаны к дню создания или явной дате начала. Время повторения не переносит эту привязку на завтра, если сегодняшний час уже прошёл.
- `now` — Date или ISO. ISO без offset трактуется в выбранной зоне. По умолчанию используются текущее время и `Europe/Moscow`.

## Архитектура и ограничения

`src/natural-date.js` задаёт явные правила статьи и извлечение фрагментов. `src/recurrence.js` превращает поддерживаемые повторения в RRULE. `src/index.js` объединяет результат, дедлайн и расчёт следующих сроков.

[Chrono](https://github.com/wanasit/chrono) остаётся резервным парсером остальных разовых фраз; [rrule](https://github.com/jkbrzt/rrule) вычисляет повторения, [Luxon](https://github.com/moment/luxon) работает с календарём и часовыми поясами. Правила вычисляются на локальной календарной шкале и переводятся в UTC на границе API.

Повторения поддерживают интервалы, части суток, будни и выходные, списки чисел месяца и дней недели, порядковые рабочие дни, кварталы, ежегодные комбинации, начало/окончание, ограниченную продолжительность и отсчёт от выполнения. [Форматы, правила совместимости с Todoist и ограничения](docs/RECURRING-DATES.md).

Несуществующее время при переходе DST отклоняется при разборе, а будущие календарные вхождения в него пропускаются. Выбор offset при осенней неоднозначности и сдвиги после выполнения пока следуют Luxon; отдельной политики нет. Проверки включают другую системную timezone, чтобы расчёт не зависел от зоны компьютера.

Совместной работы, штатного импорта CSV-архива Todoist и синхронизации офлайн пока нет. Сервер нужен для работы интерфейса; это не offline-first PWA. Проект независим от Todoist; OpenDoist — рабочее название.

Для значков проектов и разделов доступен набор эмодзи с поиском по русским и английским названиям и ключевым словам, фильтром по категориям и возможностью вставить свой эмодзи. Набор загружается с вашего сервера при первом открытии выбора; внешние API не используются.

Данные: [Emojibase](https://emojibase.dev/docs/datasets/), лицензия MIT (копия в `public/emojis-LICENSE.txt`). Чтобы пересобрать встроенный набор после обновления закреплённой dev-зависимости `emojibase-data`, выполните `npm ci` и `npm run emojis:build`. Для production используется готовый `public/emojis.json`, сборка набора не требуется.


В проектах и разделах «Входящие», «Сегодня», «Предстоящие» есть переключатель «Вид»: список, доска или календарь. Выбор сохраняется в базе отдельно для каждого раздела и доступен на всех устройствах. Настройки вида проектов также входят в JSON-экспорт.

В общих разделах доска группирует задачи по датам. В «Сегодня» календарь всегда показывает текущий день: часовая сетка, линия текущего времени и закреплённая строка «Весь день». Просроченные задачи остаются отдельным блоком над календарём. Во «Входящих» и «Предстоящих» доступны месяц, неделя, 3 дня и день.

- Доска: разделы отображаются колонками, задачи — карточками. Перетащите карточку в другую колонку или выберите раздел внизу карточки. Кнопка добавления в колонке сразу назначает раздел.
- Календарь: месяц, неделя и 3 дня; навигация по периодам и дате, часовые ячейки, добавление задачи на выбранную дату/время. Карточки можно переносить на другой день или час. Задачи без срока находятся под календарём; их можно перетащить на дату. Клик по названию открывает редактор, кружок завершает задачу.
- Календарь показывает время в часовом поясе из настроек. У повторяющейся задачи отображается ближайший срок; перенос сохраняет правило повторения. Чтобы убрать дату такой задачи, сначала отключите повторение в редакторе. Будущие повторения, длительность задач и внешние календари пока не отображаются.

Механика видов основана на документации Todoist: [доски](https://www.todoist.com/help/todoist/features/use-the-board-layout-in-todoist-AiAVsyEI), [календарь](https://www.todoist.com/help/todoist/features/use-the-calendar-layout-in-todoist-lPHRQTu0o).

В боковом меню оставлены Входящие, Сегодня, Предстоящие и проекты. Выполненные задачи и история доступны в настройках, в разделе «Архив задач». Там же выбирается сочетание для добавления задачи: Enter либо Ctrl+Enter (также ⌘+Enter на Mac); выбор сохраняется на сервере. Подсказки проектов по `#` имеют приоритет над отправкой по Enter.

В календарях «Неделя» и «3 дня» красная линия показывает текущее время в выбранном часовом поясе и обновляется каждые 30 секунд. Если текущий день не входит в видимый период, линия не отображается.

## Порядок, дочерние задачи и материалы

В списке проекта перетаскивайте задачи за **⠿**. В левой части строки подсвечивается
место до/после задачи; сдвиг правее выделяет задачу, которая станет родителем.
Вложенное дерево перемещается целиком. Ручной порядок хранится в базе.
С фокусом на маркере доступны **Alt+↑/↓** для порядка и **Alt+→/←** для вложенности.
В редакторе также можно выбрать родителя или «Самостоятельная задача». Допускается
до 10 уровней. В поисковой выдаче перетаскивание отключено; очистите поиск для изменения порядка.
Виды «Сегодня» и «Предстоящие» сохраняют сортировку по сроку, ручной порядок используется в проекте.

У каждой задачи есть описание и файлы (кнопка **✎**). Название и описание поддерживают
`**жирный**`, `*курсив*`, `~~зачёркнутый~~`, встроенный код и ссылки. В описании также
работают списки, заголовки, цитаты и блоки кода. HTML не исполняется. В редакторе есть предпросмотр.
Файлы — до **20 МБ**, не более **20 файлов на задачу**; загружаются сразу, доступны после входа
и скачиваются как вложения. Отмена редактирования текста не отменяет загрузку/удаление файлов.

Завершение родителя не завершает дочерние задачи автоматически: они остаются в списке.
Удаление родителя сохраняет дочерние задачи и поднимает их на уровень выше.
Перенос родителя в другой проект/раздел переносит всё его дерево.

## Заметки

Раздел «Заметки» в левом меню хранит тексты с отдельным заголовком. Даты, повторения и напоминания к ним не применяются, даже если такие слова есть в тексте. Сохранённая заметка открывается в режиме чтения; карандаш включает редактирование, значок глаза возвращает к чтению. После сохранения снова показывается оформленный текст. Доступны создание, удаление, поиск по заголовку и Markdown: заголовки, выделение, ссылки, списки, цитаты и блоки кода. HTML отображается как текст.

Кнопка «Сохранить заметку» или Ctrl/⌘+Enter сохраняет текст в базе. Закрытие с несохранёнными изменениями требует подтверждения. Если заметку изменили на другом устройстве, приложение не перезаписывает её молча: ваш текст остаётся в редакторе для копирования.

Для заметок нет поля `maxlength` и прикладного лимита размера запроса. Фактический размер зависит от памяти браузера/сервера, доступного диска, SQLite и настроек внешнего reverse proxy. Список получает только заголовки; полный текст загружается при открытии заметки.

Заметки входят в JSON-экспорт и полную SQLite-копию (локальную и S3). Импорт добавляет только новые ID, существующие заметки не перезаписывает. Старые JSON-файлы без заметок по-прежнему принимаются. Новые файлы следует импортировать в версию с поддержкой заметок; старый OpenDoist не восстанавливает их.
