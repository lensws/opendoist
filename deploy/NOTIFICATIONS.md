# Уведомления: email, Telegram и сводка дня

Откройте **Настройки → Уведомления и сводка дня**. Подключение каналов, сводка, напоминания и очередь доставок хранятся в SQLite на сервере. Открытый браузер не нужен. Изменения настроек доступны на всех устройствах.

## Email

1. Укажите email получателя и разрешённый почтовым сервисом email отправителя.
2. Введите SMTP-сервер, порт, логин и пароль приложения вашего почтового сервиса.
3. Для порта 587 оставьте опцию TLS с начала соединения выключенной: сервер требует STARTTLS. Для порта 465 включите эту опцию. Незашифрованный SMTP не поддерживается.
4. Включите email, сохраните и нажмите **Отправить тестовый email**.

SMTP должен быть доступен с VPS. Если отправка не проходит, проверьте ограничения провайдера VPS на исходящую почту, пароль приложения и разрешение отправлять от указанного адреса. Для собственного домена настройте SPF/DKIM/DMARC по инструкции почтового сервиса.

## Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите токен.
2. Откройте диалог со своим ботом и отправьте `/start`: бот не может первым начать личный диалог.
3. Укажите токен и числовой Chat ID получателя. Для группы добавьте бота в группу и используйте её ID (обычно отрицательный). Также поддерживается публичное имя канала вида `@channel_name`, если бот имеет право отправки.
4. Включите Telegram, сохраните и нажмите **Отправить тестовое сообщение**.

Chat ID можно узнать из поля `message.chat.id` ответа метода `getUpdates` своего бота после отправки ему сообщения. Не публикуйте ссылку с токеном и не вставляйте токен в чат с агентом. См. [документацию Telegram](https://core.telegram.org/bots/api#getupdates).

## Напомнить о задаче

В строке задачи нажмите **Напомнить**. Можно добавить до 10 напоминаний, каждое — на один или оба подключённых канала:

- **Дата и время**: самостоятельное однократное напоминание, даже если у задачи нет срока. Часовой пояс задаётся явно. Перенос срока не меняет такое напоминание.
- **До задачи**: за заданное число минут, часов или дней (до 365 дней). У задачи должны быть дата **и время**. 0 минут означает момент срока. При переносе задачи напоминание следует за сроком; при завершении повторяющейся задачи — за следующим сроком. Если срок удалён или стал без времени, такое напоминание приостанавливается до появления нового срока с временем.

Это соответствует двум режимам пользовательских напоминаний [Todoist](https://www.todoist.com/help/todoist/features/introduction-to-reminders-9PezfU). Автоматические напоминания для всех новых задач, геолокация и самостоятельное расписание повторения напоминания не добавлены.

У выполненной или удалённой задачи ожидающие отправки отменяются. Можно удалить отдельное напоминание. Уже переданное внешнему сервису сообщение отозвать нельзя.

## Сводка дня

Включите **Присылать ежедневную сводку**, выберите:

- утром — задачи на текущий день (по умолчанию 08:00);
- вечером — задачи на следующий день (по умолчанию 20:00).

Время можно изменить. Укажите часовой пояс и один или оба канала. Сводка включает невыполненные задачи на этот день, календарные повторения и отдельный список просроченных. Задачи без срока не включаются. Для повторений «после выполнения» будущая дата станет известна после завершения текущего экземпляра. Пустая сводка сообщает, что задач на день нет. Длинное Telegram-сообщение сокращается с пометкой; полный список остаётся в приложении.

Новая сводка не отправляется задним числом: если выбранное время сегодня уже прошло, первая придёт при следующем наступлении этого времени.

## Доставка и эксплуатация

Планировщик запускается вместе с `server/start.js` и проверяет очередь раз в 15 секунд. Отдельный cron или контейнер не нужен. После временного простоя напоминания догоняются в пределах 24 часов, сводки — в пределах 3 часов. Пропущенная сводка на прошедшую местную дату не создаётся заново. Более старые события пропускаются.

Неудачные доставки повторяются отдельно для каждого канала: до 8 попыток, с задержкой от минуты до часа, в пределах срока актуальности события. Отправленные события не отправляются повторно при обычном перезапуске. При аварии между приёмом сообщения провайдером и записью результата в SQLite возможен дубль — SMTP и Telegram не дают общей транзакции с нашей базой. Для SMTP используется стабильный Message-ID.

В настройках доступны последние 20 доставок и ошибки без секретов. Тестовые сообщения отправляются сразу и не попадают в очередь. В приложении работает один процесс планировщика на экземпляр; beta и production используют разные базы и подключения каналов.

Пароли SMTP и токены Telegram сохраняются в серверной базе, не возвращаются через API и не попадают в экспорт задач или браузерное хранилище. Пустое поле при сохранении оставляет прежний секрет. База и её резервные копии содержат секреты: доступ к ним должен оставаться только у администратора и приложения. При переносе копии production в другое окружение сначала отключите уведомления, чтобы не отправлять дубли.

Миграция добавляет таблицы `notification_config` и `notification_outbox`, существующие задачи сохраняются. Очередь входит в штатные SQLite-резервные копии.

## API

Все запросы требуют сессию приложения; изменения также проходят проверку Origin.

- `GET /api/notifications`: настройки без секретов и последние доставки.
- `PATCH /api/notifications`: частичное изменение секций `email`, `telegram`, `digest`. Пустой секрет сохраняет прежний; `null` удаляет его (сначала отключите соответствующий канал).
- `POST /api/notifications/test`: `{ "channel": "email" }` или `telegram`.
- `POST /api/tasks/:id/reminders`: `revision`, `kind: "before"`, `minutes`, `channels`; либо `kind: "absolute"`, `local: "2030-05-10T09:00"`, `timezone`, `channels`.
- `DELETE /api/tasks/:id/reminders/:reminderId`: текущая `revision` задачи.

Добавление и удаление напоминания меняет ревизию задачи. Список напоминаний возвращается в поле `reminders` у задачи.

## Создание задач через Telegram

В настройках Telegram включите **Создавать задачи из сообщений боту** и сохраните. Для этой функции нужен личный чат: положительный числовой Chat ID должен совпадать с ID отправителя. Сообщения групп, каналов, других пользователей и ботов игнорируются. Старые сообщения до включения функции не превращаются в задачи.

Отправьте боту текст, например `Купить молоко завтра в 18` или `Полив каждую пятницу в 10`. Он создаст задачу и ответит с распознанным сроком. Если дата неоднозначна, задача не создаётся: бот попросит уточнить формулировку. Используются язык и часовой пояс из настроек приложения; относительная дата считается от момента отправки сообщения.

Без указания проекта задача попадает во **Входящие**. Для проекта начните сообщение с `#Работа` или `#"Мой проект"`. Проект должен уже существовать и иметь уникальное имя. Команды: `/help` — примеры, `/projects` — список проектов, `/add текст` — добавить задачу. Голосовые сообщения и вложения не распознаются. Раздел можно выбрать позже в редакторе задачи на сайте.

Сервер опрашивает Telegram раз в 5 секунд через `getUpdates`, сайт обновляет список задач раз в 15 секунд, когда вкладка открыта и вы не редактируете поля. Курсор сообщений и подтверждения сохраняются в SQLite: после перезапуска задачи не дублируются. Неудачное подтверждение повторяется до 5 раз; уже созданная задача остаётся в приложении. При сбое между отправкой подтверждения и записью результата возможен повтор самого подтверждения.

Один бот должен обслуживать только один экземпляр OpenDoist: используйте отдельного бота для beta и production. Если у бота настроен webhook или работает другой получатель `getUpdates`, окно настроек покажет ошибку; приложение не удаляет чужой webhook автоматически. Подробности: [Telegram getUpdates](https://core.telegram.org/bots/api#getupdates).
