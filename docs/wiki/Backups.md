# Резервные копии OpenDoist

Откройте **Настройки → Резервное копирование**. Выберите папку или S3,
укажите частоту (час, сутки, неделя), включите расписание и сохраните.
«Создать сейчас» использует уже сохранённые параметры, даже если расписание выключено.
Перед сохранением нажмите **«Проверить подключение»**. Проверка использует текущие
поля формы; пустые поля ключей подставляют уже сохранённые ключи. Она записывает
небольшой случайный тестовый файл, читает его обратно и сравнивает содержимое,
затем удаляет. Для папки также проверяется переименование файла. Задачи и реальные
резервные копии не отправляются. Параметры, расписание и дата последней копии не меняются.

При ошибке показывается этап: запись или чтение. Если чтение и запись успешны,
но удаление запрещено, появится отдельное предупреждение: останется файл
`opendoist-check-*.txt` (в папке — каталог `.opendoist-check-*`).
После изменения полей прежнее подтверждение сбрасывается. Тест подтверждает доступ
сейчас; полный пробный бэкап кнопкой «Создать сейчас» дополнительно проверит
копирование базы целиком и доступное место для неё.

Статус показывает последнюю успешную копию, следующую попытку и ошибку, если она была.

Копия — согласованный снимок SQLite через online backup API. В него входят задачи,
проекты, разделы, ручной порядок, вложенность, описания, **все файлы задач**,
история, настройки и сохранённые ключи уведомлений/S3. Не выкладывайте копии публично.
Пароль входа из `.env`, настройки Docker/Caddy и DNS в SQLite не входят — сохраните их отдельно.
Файлы задач хранятся в самой базе, поэтому отдельный каталог вложений копировать не требуется.

Первая автоматическая копия создаётся через выбранный интервал после включения.
Следующее время сохраняется в базе и переживает перезапуск. Если сервер был выключен,
при запуске выполняется одна пропущенная попытка, затем начинается новый интервал.
После ошибки следующая попытка будет через выбранный интервал; исправив параметры,
можно сразу нажать «Создать сейчас». Одновременные запуски исключены. Для одного файла
базы запускайте только один экземпляр OpenDoist.

## Папка на сервере

Для стандартного Docker-развёртывания используйте `/app/data/backups`: папка находится
в постоянном volume. Локальный файл получает права `0600`, создаваемые папки — `0700`.
Готовая копия появляется атомарно после завершения записи. Файлы имеют уникальные имена.

Чтобы хранить копии в `/srv/opendoist-backups` на хосте, создайте папку с правом записи
для UID/GID `1000:1000` (пользователь `node` стандартного образа) и добавьте mount
в сервис `opendoist` вашего Compose-файла:

```yaml
volumes:
  - opendoist-data:/app/data
  - /srv/opendoist-backups:/backups
```

После пересоздания контейнера укажите в настройках **`/backups`**, то есть путь
внутри контейнера. При запуске без Docker укажите абсолютный путь на сервере,
доступный пользователю процесса. Папка на том же диске защищает от ошибочных изменений,
но при потере диска нужна внешняя копия, например S3.

## S3 и совместимые сервисы

- Создайте приватный bucket и ключи с правом `s3:PutObject` для нужного префикса.
  Для проверки также нужны `s3:GetObject` и `s3:DeleteObject` для объектов
  `opendoist-check-*.txt` в том же префиксе. При SSE-KMS нужны права на ключ шифрования.
- Укажите bucket, регион, access key ID и secret access key.
- Для AWS оставьте endpoint пустым; для другого сервиса укажите его HTTPS endpoint,
  например `https://s3.example.com`, без пути и учётных данных в URL.
- Для большинства совместимых сервисов оставьте path-style адресацию включённой;
  если провайдер требует virtual-hosted адресацию, выключите её.
- Префикс по умолчанию — `opendoist/`; используйте разные префиксы для production и beta.

Ключи сохраняются в базе и не возвращаются браузеру. Пустые поля при следующем
сохранении оставят прежние ключи. Копирование работает на сервере, браузер можно закрыть.
Для временного снимка S3 нужна свободная ёмкость примерно в размер базы рядом с базой.
Перед использованием расписания выполните «Создать сейчас» и проверьте статус и bucket.

Автоматическое удаление старых копий не включено. Для S3 настройте lifecycle policy
в bucket, для папки — собственный срок хранения. Размер базы растёт вместе с вложениями;
регулярно проверяйте свободное место.

## Восстановление

1. Скачайте выбранный `.sqlite` из S3 или возьмите файл из папки.
2. Остановите сервис OpenDoist. Сохраните текущую базу и её файлы `-wal`/`-shm`
   отдельно, если понадобится откат.
3. Замените файл, указанный в `DATABASE_PATH` (в стандартном контейнере
   `/app/data/opendoist.sqlite`), выбранной копией. Уберите старые файлы `-wal`/`-shm`
   из рабочего каталога после сохранения: они относятся к прежней базе.
4. Верните владельца и права файла, доступные процессу приложения (для образа — UID 1000).
   Запустите ту же или более новую версию OpenDoist. Проверьте задачи и скачивание вложений.
5. Проверьте восстановленные настройки уведомлений и копирования: они соответствуют
   времени снимка. На отдельном тестовом сервере сначала отключите внешние отправки
   и расписание, чтобы восстановленная копия не использовала production-каналы.

CLI `node server/backup.js /новый/путь/backup.sqlite` по-прежнему создаёт полный снимок,
включая вложения. JSON в **Импорт и экспорт задач** переносит задачи, описания,
порядок и вложенность, но **не двоичные файлы, пароли каналов и настройки сервера**.

## Срок хранения (TTL)

В настройках задайте **«Хранить копии, дней»**: от 1 до 3650, по умолчанию **30 дней**, в том числе для ранее настроенных экземпляров после обновления. Значение хранится в базе и общее для выбранного назначения.

После успешного ручного или автоматического backup удаляются копии старше заданного числа суток. Если новая копия не создана, очистка не запускается. Новая копия всегда остаётся. При выключенном расписании очистка происходит только после ручного backup. Смена папки/префикса не очищает прежнее место.

Удаляются только обычные файлы/объекты непосредственно в выбранной папке или S3-префиксе с точным именем OpenDoist `opendoist-<UTC-время>-<UUID>.sqlite`. Время в имени и время последнего изменения должны быть старше TTL. Символические ссылки, подпапки, временные файлы и файлы с другими именами не затрагиваются. Используйте отдельную папку/префикс для каждого экземпляра: совпадающие имена других установок в общем месте тоже считаются копиями OpenDoist.

Статус показывает последнюю очистку и число удалённых копий. Ошибка очистки показывается отдельно: новая копия остаётся успешной. Следующий успешный backup повторяет попытку очистки.

Для S3 нужны **`s3:ListBucket`** на bucket (можно ограничить выбранным префиксом) и **`s3:DeleteObject`** на копии в этом префиксе, дополнительно к правам записи и проверки подключения. Проверка подключения теперь проверяет получение списка. Object Lock может блокировать удаление.

Если в bucket включено версионирование, удаление создаёт delete marker: прежние версии продолжают занимать место. Для их удаления настройте отдельно S3 Lifecycle для noncurrent versions и expired delete markers. Приложение не удаляет версии объектов и не меняет настройки bucket.

Копии перед деплоем в `/var/backups/opendoist/{prod,beta,enki}` обслуживаются отдельно: доверенный deploy-скрипт хранит **30 дней** и очищает их после успешной выкладки. Удаляются только имена вида `YYYYMMDDTHHMMSS-<12 символов SHA>.sqlite`; ручные и предимпортные снимки сохраняются. Изменение TTL в интерфейсе на них не влияет.

Копии из ручных команд и отдельного `opendoist-update` в инструкции обновления не относятся к копиям приложения или GitHub-деплоя. Их срок хранения контролируйте отдельно.
