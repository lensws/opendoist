# Работа с OpenDoist

## Разработка и выпуск

- Обычная работа ведётся в `beta`; её push после успешных тестов автоматически обновляет https://beta.lensws.be.
- Дождись успешных CI и beta-деплоя, прежде чем сообщать, что версия доступна для проверки. Указывай проверенный commit SHA.
- Перенос в `main` и production разрешён только по отдельной прямой команде владельца в чате, например «выкатывай на основной». Согласие на настройку процесса, исправление кода или beta-деплой не является разрешением на production.
- Перед выпуском сверяй одобренный SHA, успешные тесты и фактически развёрнутую beta. Не включай новые изменения, появившиеся после проверки владельцем, без дополнительного разрешения.
- Переноси проверенный SHA в `main` fast-forward, без force push. Если ветки разошлись, согласуй изменения в beta, повтори тесты и проверку владельцем.
- Не создавай обязательный PR и не проси владельца нажимать кнопки в GitHub для обычного выпуска. Не меняй защиту ветки ради обхода проверок.
- После push в main дождись повторных тестов и деплоя, проверь healthcheck и SHA на VPS.
- Подтверждение релиза в чате — правило работы агента. Технически GitHub требует успешный `Tests and Docker build` и запрещает force push и удаление main.

## Секреты

Не выводи токены, пароли, приватные SSH-ключи и содержимое .env. Используй штатную авторизацию; секреты передавай только предназначенному клиенту, без вывода в логи. Не коммить локальные базы, резервные копии и ключи.
